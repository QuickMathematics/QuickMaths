# Curated formal environments — 2026-09-13

## Summary

QuickMaths now has a source-level experiment for curated Lean environments. The
production formal contract and certificate/trust boundary remain unchanged.
The experiment separates the existing formal corpus into five capability
profiles: basic algebra, radical algebra, limits, derivatives, and
sequences/series. Capability metadata in lesson authoring is optional loading
guidance only; it is not a verifier input, does not widen `allowed_rules`, and
does not make browser execution assessment-eligible.

## Tracked implementation changes

The formal generator now emits a `module` header, capability-scoped `public
import` lines, and the existing `QuickMathsGenerated.result` theorem/audit
name. `formal-verifier/src/quickmaths_formal/environments.py` derives canonical
capabilities from normalized goal/rule content, always includes algebra,
rejects unknown capabilities, sorts capabilities/imports, and computes a
stable source-only profile ID. Analysis profiles retain their direct
`Mathlib.Tactic.ComputeDegree` import where required; the algebra profile does
not pull radical modules or broad `Mathlib.Tactic`.

The authoring contract adds the optional `proof_spec.capabilities` array with
the allowlist `algebra`, `limits`, `derivatives`, `sequences-series`, and
`radicals`. Explicit values are validated for type, membership, duplicates,
and inferred coverage. An absent array stays absent in normalized legacy
specifications. Lesson Studio accepts comma-separated values, preserves them
through edits/exports, and treats blank input as automatic inference.

The web loader provides two bounded primitives. The artifact cache verifies
descriptor size and SHA-256 before use, deletes corrupted entries, deduplicates
concurrent downloads, and reports when quota prevents a durable cache write.
The environment pool serializes selection, reuses a worker for the same
environment/representation, disposes the previous worker when switching, and
disposes the active worker at shutdown. Shared content-addressed cache entries
can therefore be reused across profiles without claiming that a browser cache
is an offline verifier.

The curated experiment scripts inventory the complete corpus, record explicit
environment/profile membership, build shared public-module packs, and prepare
the worker. Packs use explicit artifact maps for `.olean`, `.ir`, and
`.ir.sig`; missing or ambiguous artifacts fail closed. The export list is
derived from the actual staged Lean archives and retains only the runtime ABI,
initializer entrypoints, boxed dispatch symbols, and required entrypoints.
Runtime/meta initializer phases are included for public modules. Snapshot
bindings include the runtime WASM and JavaScript hashes, exact header, driver,
setup map, profile, and Node version. Snapshots are generated by that exact
WASM binary through the pinned Node driver, not by the native compiler.
The final build-cache check additionally hashes the selected compiled artifact
bytes and file layout, so changed oleans/IR invalidate cached snapshots even at
unchanged source pins. This cache-key hardening followed the measurements; their
original manifest identities are retained unchanged. It does not alter the
measured runtime or snapshot bytes. Rebuilding those earlier cached snapshots
with the final script deliberately regenerates them once.

## Native verification

Final native acceptance confirms 122/122 positive fixtures and 71/71 negative
fixtures using the existing 60-second per-proof budget. The last three positive
controls passed on sequential retries: `guarded_cancellation`,
`difference_quotient`, and `sqrt_square_nonnegative`. These are native kernel
results. Certificate and trust code were unchanged.

Focused checks pass: 16 Python authoring/export/boundary tests, 10 generator and
environment tests (including six curated-environment invariants), 12 JavaScript
binding/capability/loader tests, three Lesson Studio formal tests, four symbol-
lookup parity tests, and two export-list tests. The import compatibility check
and real-certificate boundary check pass too. No full unrelated app suite was run.

## Curated payloads

All sizes below use MiB (1,048,576 bytes). The shared runtime adds **16.94 MiB**
compressed to either representation. Module counts include Lean, Std, Batteries,
and other transitive dependencies as well as Mathlib.

| Environment | Modules | Module packs, gzip MiB | Exact-WASM snapshot, gzip MiB | Snapshot generation, seconds |
| --- | ---: | ---: | ---: | ---: |
| Algebra | 2,455 | 179.9 | 135.5 | 34.2 |
| Radicals | 2,998 | 212.3 | 162.8 | 74.7 |
| Limits | 3,451 | 255.1 | 199.1 | 61.9 |
| Derivatives | 4,064 | 304.8 | 238.7 | 67.2 |
| Sequences/series | 3,919 | 289.8 | 226.6 | 66.5 |

Profiles always include algebra; analysis profiles also include radicals.
The lists are complete transitive closures of the selected public roots, with
implicit `Init` and every recorded source import. This establishes a reproducible
closure for these roots, not a proof of the globally smallest possible Lean
library. Root lists, every module name, artifact hashes, and exact byte counts
are retained in [the environment catalog](../../experiments/browser-lean/results/curated/environments.json)
and [payload evidence](../../experiments/browser-lean/results/curated/payload-size.json).

Module packs share content across profiles: **all five together use 304.93 MiB**
compressed, plus the runtime. Separate snapshots duplicate shared environments:
all five use **962.69 MiB**, plus the runtime. Snapshots save roughly 22–25% for
one environment, but consume over three times the library cache space if all
five are retained. Snapshot generation time excludes subsequent gzip compression.

## Browser measurements

The experiment uses headless desktop Chromium **140.0.7339.16** on this Windows host (8 physical
cores, 16 logical CPUs, about 32 GiB RAM), normal browser stack limits, four
pthread pool workers and two Lean task workers. Each measurement starts beside
an actual QuickMaths mastery map with no verifier. Gzip artifacts are served
from localhost. These are local loading/initialization observations, not an
internet-download or physical-mobile benchmark.

The snapshot runs completed twice per environment. First-ready time includes
runtime loading, environment restore, and a successful audited `True` control.
The first algebra run has an empty artifact cache; later first visits reuse
the shared runtime cache. The second visit always uses a fresh worker and the
verified artifact cache.

| Snapshot environment | First visit ready, seconds | Cached fresh worker ready, seconds | Successful corpus median, ms | Incremental peak USS, GiB (both runs) |
| --- | ---: | ---: | ---: | ---: |
| Algebra | 5.98 | 5.68 | 140 / 158 | 1.95–2.29 |
| Radicals | 6.63 | 6.14 | 190 / 191 | 2.54–2.57 |
| Limits | 7.04 | 6.58 | 190 / 190 | 2.37–2.39 |
| Derivatives | 7.95 | 7.38 | 236 / 241 | 2.65–3.24 |
| Sequences/series | 7.56 | 7.21 | 328 / 346 | 2.73–2.74 |

The medians exclude failing proofs, initialization/rejection controls, and warm
repeats. Five additional warm repetitions of a successful proof are recorded
per run; they are proof-specific measurements, not a universal verification
latency. Individual timings and source hashes are in the retained evidence.

After terminating the verifier worker and closing its probe page, the measured
browser process family returned to within roughly 21 MiB of baseline after
three seconds in the snapshot runs. Small negative deltas reflect baseline/GC
variation. This is an observed release of private resident memory, not a promise
that every browser immediately returns allocations to the OS. The final snapshot
browser profile occupied 1,035,072,106 logical file bytes, including browser
metadata; verified compressed artifact bodies are reported separately.

One complete module-pack corpus pass was run per environment, in the same
progression with shared caching. Every trapped worker was replaced, and the
next proof waited for the same environment to load again.

| Module environment | First visit ready, seconds | Successful corpus median, ms | Incremental peak USS, GiB |
| --- | ---: | ---: | ---: |
| Algebra | 10.66 | 144 | 2.26 |
| Radicals | 10.24 | 188 | 2.29 |
| Limits | 11.81 | 196 | 2.55 |
| Derivatives | 13.23 | 242 | 2.81 |
| Sequences/series | 14.06 | 344 | 2.84 |

Snapshots reduce first-ready time by about 35–46% in this local comparison.
Once an environment is ready, successful proof latency is similar between
representations; snapshots are not a faster proof engine. There is no consistent
peak-memory advantage for snapshots. Module workers returned within roughly
28 MiB of baseline after disposal. Their final browser profile occupied
345,305,364 logical bytes, versus 1,035,072,106 for snapshots. Cache bodies were
confirmed present in the tested Chromium Cache API, but the experiment does
not cache every bootstrap dependency or establish offline app availability.
These are a small number of observations on one desktop, not confidence
intervals or a benchmark of current Chrome/Safari releases.

## Corpus outcomes and trust boundary

Native verification passes **122/122 positive cases and 71/71 negative cases**.
Module packs and exact-WASM snapshots pass the same **105/122 positive cases**
in every completed matching-environment Chromium run:
algebra 3/3, radicals 2/2, limits 20/20, derivatives 11/16, sequences/series
69/81. The remaining 17 all report `Maximum call stack size exceeded` in the
module run and both snapshot runs; the
[failure inventory](../../experiments/browser-lean/results/curated/failures.json)
records the exact cases. They are not proved
false and do not receive certificates. Snapshots accelerate environment loading
but do not remove proof-time interpreter/trampoline stack limits.

Every environment records all 193 corpus rows. Its canonical-header positive
cases execute unchanged; other positives explicitly return
`different_environment_required`. All 71 negative requests execute the unchanged
production preflight and remain rejected (70 `needs_justification`, one
`ambiguous_input`). These preflight and routing rows are not kernel passes and
are not a claim that every narrow environment proves all 122 statements.
Every initialized/replacement worker also rejects an invalid `False := by rfl`
control and a `sorry` control under the existing axiom policy.

A trapped worker is destroyed before the next case. The first exploratory
module run reused a worker after a trap, so it is excluded from the retained
validated results. Native retry evidence, complete per-environment matrices,
canonical source hashes, rejected controls, browser versions, cache status,
and memory measurements are retained under
[results/curated](../../experiments/browser-lean/results/curated/).
Large machine-readable catalogs and run evidence are compact JSON and marked
as generated in `.gitattributes`; the human-readable measurements and failure
summaries remain formatted for review.

The generator's source and theorem name are unchanged between the native and
aligned browser paths: there are **no import substitutions**. New public-module
headers produce new source hashes through the existing binding mechanism. The
certificate schema, verifier pins, axiom allowlist, mathematical coverage and
production trust implementation are unchanged. A freshly generated native
certificate passes the app boundary; rehashed browser identities and null
certificates are rejected. Every experimental result is explicitly
`assessment_eligible: false` with `certificate: null`.

## Runtime repairs and remaining limits

Profiling found that the generated Emscripten `__dlsym_js` routine enumerated
the entire export table on ordinary symbol lookups. The optimized hook checks
enumerable membership directly and preserves enumeration only when installing
a new function-table entry that needs its original symbol index. It preserves
stub checks, ordering, late-added exports, and the slow-path ABI; exact-hook
parity tests cover these cases. This repair, rather than a relaxed proof policy,
removed the earlier multi-minute import bottleneck.

The exact-WASM `qm-environment-v1` snapshot stores the imported environment plus
regular initializer indices. It excludes questions, proof bodies, certificates,
and CLI command/task trees. The matching Node 24.21.0 build driver uses an 8 MiB
JavaScript stack for artifact generation; browser benchmarks use ordinary stack
limits. Restore replays initializers and retains the imported region only for
the worker's lifetime. Verified compressed bytes stream into the worker;
temporary snapshot files are released after restore.

**This is not ready to replace production verification.** Seventeen existing
proofs still fail in Chromium and peaks of 2–3+ GiB are not evidence of mobile
viability. No physical Android Chrome or iPhone Safari was available for this
update; desktop results are not substituted for those tests. A native-WASM
exception build is a possible next investigation for JS trampoline stack
pressure, but has not been built or validated here and is not claimed as a fix.

The current pthread runtime still requires cross-origin isolation. These runs
use local COOP/COEP headers and do not establish deployment on ordinary GitHub
Pages. The reference implementation documents its shared-memory/header
requirements and browser stack limitations in its
[README](https://github.com/cauli/lean4-wasm-in-browser/blob/main/README.md).
There is also a delivery tradeoff: these single snapshot files exceed Git's
100 MiB file limit, and retaining all snapshots plus the runtime leaves little
or no room within the documented 1 GB published-site allowance. A future Pages
deployment would need deliberate packaging and isolation; the large binaries
are not committed with this update. See
[GitHub repository limits](https://github.com/github/docs/blob/main/content/repositories/creating-and-managing-repositories/repository-limits.md)
and [Pages limits](https://docs.github.com/en/pages/getting-started-with-github-pages/github-pages-limits).

Use shared module packs as the cache-efficient baseline for further work, and
retain exact-runtime snapshots as an optional measured acceleration for selected
environments. Do not ship either as assessment authority until the entire
relevant kernel corpus passes and device memory/hosting behavior is validated.
Historical browser reports retain their original pins, headers and measurements.

## Reproduction

Keep all runtime, downloads, profiles, generated packs, and snapshots under
the ignored X: workspace. From the repository root:

```powershell
python experiments/browser-lean/curated-corpus.py
```

From the F-backed matching build environment, after checking out Lean at
`6a10ac8c22beadecabdbb0919c2b50214762f91d`, Mathlib at
`42a3845c6d7ec6866eefa4cc327a306a0c4a7d3c`, and applying
`lean-6a10-curated.patch`:

```bash
scripts=/mnt/x/QuickMaths/experiments/browser-lean
bash "$scripts/install-snapshot-node.sh" "$PWD"
python3 "$scripts/prepare-curated.py" "$PWD"
python3 "$scripts/prepare-curated.py" "$PWD" --snapshots
```

From Windows, use the existing formal Python environment and installed
Playwright browsers. Run the representations sequentially to avoid competing
build or benchmark workloads:

```powershell
. X:\QuickMaths\scripts\formal-env.ps1
python experiments/browser-lean/benchmark.py --suite curated --mode modules --group all --label curated-validated-modules --repeat 1 --timeout 900
python experiments/browser-lean/benchmark.py --suite curated --mode snapshot --group all --label curated-validated-snapshots --repeat 2 --timeout 900
python experiments/browser-lean/summarize-curated.py
```

## User and author implications

Authors may leave capability metadata blank and rely on inference, or provide a
validated explicit list as a hint for curated loading. The hint does not grant
rules, alter pinned environments, create certificates, or bypass trust checks.
Learners continue to receive credit only through the existing fresh native
certificate path. Browser experiments can diagnose payload, initialization,
cache, worker-disposal, and snapshot behavior, but their outputs remain
ineligible for assessment.

Profile IDs identify canonical source/import environments only. They are not
runtime manifest hashes and do not attest to a particular WASM binary. Runtime
asset hashes, explicit artifact-map hashes, setup-map hashes, driver hashes,
and exact-WASM snapshot bindings provide the separate provenance needed for an
experiment. Shared caches reduce repeated downloads; single-worker disposal
prevents stale environment reuse. A failed initialization or unavailable
snapshot remains unavailable and is never counted as a kernel pass.
